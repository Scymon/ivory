# Ivory Product Vision

## What Ivory is

Ivory is a structured knowledge environment for personal and organizational use.

Ivory begins by independently re-engineering the functional baseline of the current Obsidian desktop experience. That familiar open knowledge environment is Ivory V0. Ivory then adds a durable structural core so users do not have to invent an entire information architecture from an empty field.

Ivory is intended to make information easier to collect, classify, relate, understand, retrieve, reuse, and publish.

## V0: the open field

V0 targets practical functional parity with the current Obsidian desktop application: local vaults, Markdown authoring and rendering, Properties, Bases, Canvas, links/backlinks, graph, search, workspace behavior, core features, appearance/customization, commands, settings, plugin infrastructure, CLI/deep-link capabilities, and the surrounding desktop interaction model.

The goal is not to copy Obsidian's private implementation or proprietary assets. The goal is to independently build Ivory so that the general-purpose environment feels familiar and provides equivalent categories of capability.

An existing Obsidian user should be able to bring an ordinary vault to Ivory and use the major current desktop workflows before relying on any Ivory-specific structural features.

See `V0-OBSIDIAN-PARITY.md` for the product scope.

## V1+: the Ivory pillar

Where an open-ended notes environment asks the user to invent their own structure, Ivory adds a coherent structural pillar.

Information should not exist only as isolated notes. Ivory should be able to treat knowledge as identifiable things with types, properties, relationships, sources, and context.

A person should be able to use Ivory to structure a personal body of knowledge. A company should be able to use the same core to structure organizational knowledge. Industry-specific needs should extend the core rather than require a different application.

## Product direction

Ivory should provide:

- current general-purpose desktop knowledge capabilities as the V0 baseline;
- local-first knowledge storage;
- Markdown as a durable human-readable format where appropriate;
- Properties and Bases as first-class information interfaces;
- Canvas and graph/spatial relationships;
- linked and relational knowledge;
- typed information and schemas;
- strong navigation, search, graph, and workspace capabilities;
- a native Ivory plugin ecosystem;
- practical compatibility with useful Obsidian plugins where support is explicitly implemented;
- structured context that can be used by humans, publishing systems, and AI systems;
- personal and business configurations built from the same underlying architecture.

## What Ivory is not

Ivory is not an Obsidian theme, plugin bundle, wrapper, or fork.

Ivory is not intended to reproduce Obsidian's private implementation. Similar capabilities are independently engineered around Ivory's own architecture.

Obsidian compatibility is a bridge into an existing plugin ecosystem and migration path. It does not define Ivory's internal architecture or long-term limits.

## Long-term objective

Ivory should become a knowledge substrate: one structured source of knowledge that can support human navigation, internal organizational understanding, research, AI context, and selective public publishing without requiring separate disconnected representations of the same information.
